# Contributing

Thanks for helping. uifiles is a shadcn/ui registry on Base UI; the contributor rules live in
[`AGENTS.md`](./AGENTS.md) and apply to people and agents alike. This file covers the workflow.

## Setup

Node 24 (`.nvmrc`) and pnpm 11 (`packageManager` in `package.json`). Use `pnpm` for
everything; never `npm install` or `npx`.

```bash
pnpm install
pnpm exec playwright install chromium   # once; the browser tests and e2e need it
pnpm registry:build                     # tokens → validate → public/r
pnpm dev                                # http://localhost:3000
```

## Making a change

- **Registry items.** Read `AGENTS.md` "Rules for registry work" first and, for AI Elements
  ports, `docs/porting-ai-elements.md`. Every new item ships with a registry entry whose
  `description` is written for retrieval, a preview page under `app/preview/<name>/`, and a
  browser test with axe under `tests/browser/` that uses the helpers in `tests/a11y.ts`.
- **Tests.** Port upstream's test file first, then cover every prop and state; name tests by
  the behaviour they assert. `tests/setup.ts` fails a browser test that logs through
  `console.error` or `console.warn` (`allowConsole()` opts a test that asserts a warning out).
  A test file must pass three runs in a row. The recipe, with the Vitest browser-mode
  gotchas, is in `AGENTS.md` "Tests".
- **Tokens.** Edit `app/globals.css`; the `cssVars` of `registry/base` are generated by
  `pnpm registry:build`, and the regenerated `registry/base/registry.json` is committed.
  Never edit `public/r`.
- **Overlap policy.** Do not port `message`, `conversation`, `attachments`, `shimmer` or
  `loader` from AI Elements; shadcn ships them. The resolution table is in
  `docs/architecture.md`.
- **Docs.** If a change alters a command, a count or a rule, update `AGENTS.md`,
  `README.md` and `docs/` in the same PR. `tests/unit/site.test.ts` checks some of them.

## Before opening a PR

```bash
pnpm gate        # format:check → lint → typecheck → registry:validate → test → build
pnpm test:e2e    # Playwright + axe over every preview page (CI runs this too)
```

CI runs the same steps with `pnpm registry:build` before the tests under coverage
(`pnpm test:coverage`, which fails any file under `registry/**` or `lib/**` below 80% lines,
80% functions or 70% branches), a check that the generated registry files are committed,
`pnpm test:e2e` against the production build with `NEXT_PUBLIC_BASE_URL` set (desktop and
375 px, with every request to a host other than localhost aborted), and `pnpm audit` last.

Open `/preview/<name>` in `pnpm dev` and look at the change in both themes; server rendering
and hydration are not exercised by the browser tests. `pnpm typecheck` runs with
`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess` and `noUnusedLocals` on, because
registry sources are copied into consumer projects with unknown compiler settings.

Commits follow [Conventional Commits](https://www.conventionalcommits.org/) with a scope
(`feat(ai): port sources`, `fix(preview): main landmark`, `docs: architecture`). One item per
PR when porting. Use the pull request template; the checklist is what reviewers look for.

## Reporting bugs and requesting components

Use the issue templates. For a component request, say whether shadcn/ui or AI Elements
already ships it.

## Licensing

Contributions are accepted under the repository's MIT licence. Ports from AI Elements keep
the Apache-2.0 header; the licence copy is `licenses/APACHE-2.0-ai-elements.txt` and
`NOTICE` records the modifications. Do not add another `LICENSE*` file at the repository
root: GitHub's licence detector reads every one of them and would report the repository as
"Other" instead of MIT.
