## Findings (most severe first)

### E1. Environment: the QA server was a stale `next start` serving HTML for a build that no longer existed — severity: n/a for the product (invalidated pass 1); low as a process hazard
- Where: the sandbox's `pnpm start` (PID 5411, started 23:27:00) vs `.next` rebuilt at 23:40:46 by `pnpm gate` (which runs `build`); `playwright.config.ts:18` (`reuseExistingServer: !CI`).
- What: every 200 page's HTML linked `/_next/static/chunks/3g4d4pl8l91w7.css`, which the rebuild had replaced by `0jgcpcuv4iy7d.css`; the server answered `500 Internal Server Error` for it (`x-nextjs-cache: HIT` on the HTML), so every page rendered without Tailwind, tokens, Streamdown or KaTeX CSS. Only the 404 pages (first requested after the rebuild) linked the new chunk. The served HTML was otherwise byte-identical to `.next/server/app/*.html` (JS chunk lists identical), so I fulfilled the stale request from disk to keep working; the lead then restarted the server and the whole suite was re-run. Pass-1 and pass-2 verdicts agreed everywhere.
- Evidence: `pass1-stale/probe-home.mjs` output (`500 … 3g4d4pl8l91w7.css`, overflow at 375 px, `display: inline` links, axe `color-contrast` `#9e9eff on #ffffff` in "dark"), `pass1-stale/served-task.html` vs `.next/server/app/preview/task.html` (2 differing lines, both the chunk name), `pass1-stale/sweep.json`.
- Why it matters: anyone who follows README's "run `pnpm gate` before every PR" while a `pnpm start` is up on `:3000` gets exactly this, and a local `pnpm test:e2e` would reuse that server. Not a code defect in the repo.
- Proposed fix: none required in code; a one-line note in CONTRIBUTING ("stop `next start` before `pnpm gate`/`pnpm build`") or `reuseExistingServer: false` locally.

### N1. Two horizontally scrolling regions are still not keyboard reachable at phone width (F3 residual) — severity: high
- Where: `app/page.tsx:33` (`<pre class="overflow-x-auto …">` install snippet, no `tabIndex`); `registry/ai/response.tsx:23-96` (the marker only handles `[data-streamdown="code-block-body"]`; Streamdown's table wrapper `div.border-collapse.overflow-x-auto` is not marked).
- What: at 375 px in both themes axe reports `scrollable-region-focusable` (impact **serious**, WCAG 2.1.1) on `/` (`pre`, scrollWidth > clientWidth) and on `/preview/response` (`.border-collapse`, sw 312 / cw 289). The table's third column is cut off ("Highes", "Lowes") and a keyboard user cannot reach it. Round 1 named all three surfaces; the fixes covered `code-block` and Streamdown code bodies only.
- Evidence: `sweep.json` → `/ light-mobile` / `dark-mobile` and `/preview/response light-mobile` / `dark-mobile` violations; `mobile.mjs` response: `[{sd:"code-block-body", tabindex:"0"}, {cls:"border-collapse overflow-x-auto…", tabindex:null, sw:312, cw:289}]`. `shots/preview_response--dark-mobile.png`, `shots/home--light-mobile.png`.
- Why it matters: the only two axe *violations* left on the site, both serious, on the home page and the flagship `response` item; any assistant answer with a wide table on a phone has the same gap. The desktop-only e2e project cannot see either.
- Proposed fix: `tabIndex={0}` (+ `role="region" aria-label="Install command"`) on the home `pre`; extend the response marker's selector to Streamdown's table wrapper (`[data-streamdown="table-wrapper"]` or the `.border-collapse.overflow-x-auto` div) using the same claimed-by-React check; add a 375×812 Playwright project (or a second viewport in `previews.spec.ts`).
- Test written: none (lens rule). Repro: `node mobile.mjs`, `node sweep.mjs /,/preview/response`.

### N2. Chat: a sent attachment stays in the composer as a removable chip until the reply finishes — severity: medium
- Where: `registry/blocks/chat/components/blocks/chat.tsx` `ChatComposer.handleSubmit` (`return onSubmit(message)`), `registry/blocks/chat/page.tsx:22` and `app/preview/chat/page.tsx:41` (`onSubmit={({ text, files }) => sendMessage({ text, files })}` returns the transport promise); `registry/ai/prompt-input.tsx` clears attachments only when an async `onSubmit` resolves (upstream #126, kept by `fix-prompt-input`).
- What: paste an image, type, Enter → the user row shows the file immediately, the text draft clears immediately (`form.reset()`), but the composer keeps the `pasted.png` chip with its Remove button for the whole reply (`attachmentClearedAt` = `readyAt` = 818 ms for the short scripted turn; with a real model this is the full generation time). Backspace in the empty textarea during the reply removes the chip (PromptInput's "remove last attachment" shortcut), so the user can "un-attach" a file that was already sent. `sendMessage` from `useChat` never rejects (errors go to `error` state), so nothing is gained by returning it.
- Evidence: `probe3.mjs` → `sentAt: 6 ms, draftClearedAt: 6, attachmentClearedAt: 818, readyAt: 818`; `probe4.mjs` → mid-stream `composerChips: ["pasted.png"], transcriptChips: ["pasted.png"], removeButtons: 1`, Backspace → `composerChips: 0` while still streaming. `shots/chat-24-attachment-lingers-midstream.png` (same file in the user bubble and in the composer, Stop button showing).
- Why it matters: the composer says "not sent yet" while the transcript says "sent"; on a slow model that is tens of seconds of contradictory state in the showcase block.
- Proposed fix: in the block's page wrappers use `void sendMessage(...)` (do not return the promise), or clear attachments explicitly on submit (`usePromptInputAttachments().clear()` from `ChatComposer`), and say in `docs` that `onSubmit` should not return a long-lived promise. The block test "renders a files-only user turn as attachments without an empty bubble" should also assert the composer chip is gone right after the send.

### N3. Inline-citation: the card's carousel cannot be operated from the keyboard, so the second source is unreachable — severity: medium (inherited)
- Where: `registry/ai/inline-citation.tsx` (`HoverCardTrigger` → Base UI `PreviewCard`, a non-modal popup with no focus management); upstream (Radix HoverCard) identical.
- What: after F5 the badge is a button and focus opens the card, but Tab from the badge moves to the next badge (then `body`); the popup's Prev/Next never receive focus, and no arrow-key handling exists on the badge. Sources 2..n of a multi-source citation are therefore mouse-only.
- Evidence: `probe2.mjs`: "open via Tab, then Tab once more" → active `base-ui.com` badge, card count 1; "Tab again" → active `body`, card closed; "Enter" → nothing. `shots/probe-citation-keyboard.png`.
- Why it matters: WCAG 2.1.1 for the paging function; citations are the only route to sources in a response.
- Proposed fix: on the badge, handle ArrowLeft/ArrowRight (call the carousel api) and Home/End, or render the card with a roving tab stop; document the limitation in `docs` meanwhile (touch has the same gap, as the fixer noted).

### N4. Suggestion chips that are partially visible are not scrolled into view when focused — severity: low
- Where: `registry/ai/suggestion.tsx` (`ScrollArea` with hidden scrollbar); no `onFocus` handling.
- What: Tabbing through `/preview/suggestion`, chip 4 lands with 225 px of it (and its focus ring) outside the scroller and chip 6 with 12 px outside; chips that were fully hidden are centred. A control page with a bare `overflow:scroll` box (`probe4.mjs`) behaves the same in Chromium (4/8 clipped), so this is the browser's sequential-focus scrolling (no scroll when partially visible), which the component must handle itself. Round 1's "Verified OK" only checked the last chip.
- Evidence: `probe3.mjs` → `"Best practices for React devel: 966-1233 (vp 272-1008, sl 0) clip=225"`, `"How to optimize database queri: 768-1020 … clip=12"`. `shots/probe-suggestion-clipped-4.png`.
- Why it matters: WCAG 2.4.11 (AA) passes (not entirely hidden) but 2.4.12 fails and the focus ring's right edge is cut off; users tabbing through suggestions cannot read the focused chip.
- Proposed fix: `onFocus={(e) => e.currentTarget.scrollIntoView({ inline: "nearest", block: "nearest" })}` on `Suggestion` (or `scroll-padding-inline` plus `scrollIntoViewIfNeeded`).

### N5. Code-block: multiple scroll regions share the default landmark name "Code" — severity: low
- Where: `registry/ai/code-block.tsx:474` (`"aria-label": ariaLabel = "Code"`, `role="region"`).
- What: on `/preview/code-block` at 375 px two overflowing blocks both become `role=region` named "Code" → axe `landmark-unique` (moderate). Any transcript with two overflowing `CodeBlock`s hits it.
- Evidence: `sweep.json` `/preview/code-block light-mobile` / `dark-mobile`.
- Proposed fix: derive the default name from the filename/language when present ("use-debounce.ts code", "JSON code"), or use `role="group"` (named, not a landmark) for the scroller.

### N6. Checkpoint tooltip is visual-only (F23 residual) — severity: low

- What: the tooltip "Restore the workspace to this point" opens on hover and on keyboard focus but is not exposed to AT; the fix for F23 only covered `PromptInputButton`.
- Evidence: `interact.mjs` checkpoint: `describedby: null` with the tooltip open. `shots/int-checkpoint-tooltip-focus.png`.
- Proposed fix: the same `sr-only` description pattern as `PromptInputButton` (or extract it into `components/ui/tooltip.tsx`).

### N7. `/preview/model-selector` depends on `https://models.dev` (F13 recommendation) — severity: low (medium for CI robustness)
- Where: `registry/ai/model-selector.tsx:256`, `app/preview/model-selector/page.tsx` (four logos incl. the decorative `ModelSelectorLogoGroup`).
- What: every load issues 3 third-party requests; when blocked (this sandbox, corporate networks, offline, an egress-less CI runner) the console gets 3 `Failed to load resource: net::ERR_TUNNEL_CONNECTION_FAILED` errors. The component now hides itself cleanly (no glyph, no layout jump), so the user-facing half is fixed. But `e2e/previews.spec.ts` asserts `collectPageProblems(page)` is empty, and `collectPageProblems` records those console errors, so the `preview/model-selector` e2e test passes only where `models.dev` is reachable.
- Evidence: `sweep.json` `/preview/model-selector` → `external.failed: openai.svg, anthropic.svg, google.svg` in all four contexts; `interact.mjs` logo imgs `hidden: true, display: none`.
- Judgement: a docs preview should not depend on an external host. Recommendation: keep the component as upstream designed it, but let the preview pass a local `src` (add the optional `src` override the fixer deferred, or an `onError`-friendly local logo set under `public/`), and have `collectPageProblems` ignore `models.dev` resource failures (or vice-versa) so the e2e suite does not hinge on egress.
