## Not fixed and why

- chat-block-and-leaves:F11 — not wired (documentation only, per the brief); the `docs` sentence is under **Registry entry changes**. Wiring `addToolApprovalResponse` needs a design decision (which tool parts get a `Confirmation`, how `reason` is collected) and a new `onToolApproval` prop; recommend a follow-up item once `@uifiles/confirmation`'s API settles.
- "Stopped" label for an aborted tool call — the `ai` state union has no cancelled state and `ToolHeader` renders its own badge, so the block maps an aborted `input-available` call to the neutral "Pending" header rather than inventing a badge (which would mean duplicating `ToolHeader`'s markup plus `badge`/`collapsible` deps). "Pending" is also right for a client-side tool awaiting `addToolOutput` (status `ready`, part `input-available`), which the block cannot tell apart from a stop. See **Requests for other owners** for a proper "Stopped" state.
- "ChatEmpty keys suggestions by their text" (note) — left; duplicate suggestions are a consumer error and an index key would need a lint suppression for no behaviour gain.
