## Not fixed and why

- app-tooling-oss:F2, GitHub API detection — **needs owner decision.** I verified GitHub's licence detector (licensee) at source: `lib/licensee/project_files/license_file.rb` scores a root file named `LICENSE-<anything>` as a licence file (`/\A(un)?licen[sc]e[-_][^.]*…/` → 0.70), and `lib/licensee/projects/project.rb` `#license` returns `other` whenever two matched files carry different licences. With the full Apache-2.0 text in `LICENSE-ai-elements` (as the brief asked), licensee will match it as Apache-2.0, so the API/shields badge will read "Other"/NOASSERTION while the repo page lists "MIT, Apache-2.0 licenses found". Before this change the 12-line boilerplate did not match anything, so only the (modified) MIT file counted, which is why the report attributed the "Other" to the appended paragraph alone. Both statements are now true: the repo *is* MIT with Apache-2.0-derived files. If a single "MIT" badge matters more than a root-level licence copy, the one-line remedy is `git mv LICENSE-ai-elements licenses/apache-2.0-ai-elements.txt` (licensee scans only the repository root; Apache §4(a) is satisfied by a copy anywhere) and updating the four references (`NOTICE`, `README.md`, `AGENTS.md` layout row, `docs/architecture.md` §1).
